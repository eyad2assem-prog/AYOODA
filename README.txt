# نظام إدارة السوبر ماركت

هذه نسخة أولية متكاملة قابلة للتوسعة، تعمل من المتصفح على الكمبيوتر والموبايل، وتتصل بقاعدة Supabase واحدة لمزامنة الأجهزة.

## الملفات
- `index.html`: واجهة النظام.
- `supabase_setup.sql`: إعداد الجداول والصلاحيات ودوال ترحيل فواتير البيع والشراء.
- `README.txt`: خطوات التشغيل.

## قبل التشغيل
1. افتح `index.html` في محرر VS Code.
2. ابحث في بداية JavaScript عن `PASTE_YOUR_SUPABASE_PUBLISHABLE_KEY_HERE`.
3. ضع **Publishable key** الخاص بمشروع Supabase فقط في `CONFIG.key`.
   - لا تضع `service_role` أو أي Secret key داخل ملف HTML.
4. من Supabase افتح SQL Editor، وخذ نسخة احتياطية من قاعدة البيانات أولاً.
5. راجع ملف `supabase_setup.sql` ثم شغّله مرة واحدة.
   - الملف additive ويحافظ على الجداول والبيانات السابقة، لكنه يحدّث سياسات جدول المنتجات لتوحيد صلاحيات الحسابات المسجلة.
   - لا تشغّله مرة ثانية دون مراجعة، خصوصاً إذا كانت لديك سياسات أو جداول معدلة يدويًا.
6. شغّل الصفحة عبر VS Code Live Server أو أي استضافة HTTPS.

## حسابات المستخدمين
- أنشئ كل حساب من Authentication > Users.
- صيغة البريد المستخدمة في شاشة الدخول: `username@store.local`.
- أضف صفاً في جدول `profiles` بنفس UUID الخاص بالمستخدم، وضع `username`.
- كل المستخدمين المسجلين لهم صلاحيات التطبيق نفسها حسب إعداد RLS في ملف SQL.
- لا تشارك حساباً واحداً بين كل الأجهزة؛ استخدم حساباً مستقلاً لكل شخص لتسجيل من نفّذ العملية.

## ملاحظات تشغيل مهمة
- لا تستخدم بيانات حقيقية قبل تجربة النسخة على بيانات اختبار.
- كل كمية مخزون محفوظة بالقطعة؛ اختيار الكرتونة يحوّل العدد إلى قطع باستخدام `units_per_carton`.
- الصلاحية تُسجل لكل دفعة في `product_batches` عند إدخال تاريخ صلاحية في فاتورة الشراء.
- البيع يستهلك الدفعات الأقدم انتهاءً أولاً (FEFO)، ثم يخصم إجمالي الرصيد.
- البيع والشراء يمران بدوال SQL ذرية؛ لا تعدّل رصيد المخزون يدوياً.
- يجب أن تكون قيمة `products.id` من النوع النصي كما في قاعدة البيانات الحالية.
- النسخة الحالية لا تنفّذ مرتجعات أو ديون/أرصدة آجلة أو طباعة فواتير حرارية أو مسح باركود بالكاميرا. هذه مراحل تالية.
- إذا كانت أسماء الأعمدة في جداولك الحالية مختلفة عن الملف، أوقف التنفيذ وأرسل صورة/رسالة الخطأ بدلاً من حذف الجداول أو إعادة إنشائها.

## ملاحظة أمنية
المفتاح Publishable آمن للواجهة بشرط ضبط RLS. لا تستخدم مفاتيح Secret/service_role في المتصفح. دوال SQL تعمل بصلاحية محددة وتتحقق من وجود جلسة مستخدم.
